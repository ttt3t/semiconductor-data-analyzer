# 本地版本管理

本项目已建立 Git 版本库，主分支为 `main`，沿用现有 GitHub 仓库的历史提交。本次设置只在本地保存当前源码，没有推送到 GitHub。

## 在 Visual Studio 中使用

1. 打开项目后，在菜单选择“Git → Git 更改”。
2. 修改代码后，点击文件查看差异，确认本次需要保存的内容。
3. 填写提交说明，例如“修复多晶圆统计”，选择“全部提交”即可保存一个本地版本。有关联但尚未跟踪的新源码文件也需要纳入提交。
4. 在“Git → 管理分支”或“Git 存储库”窗口查看历史，比较提交之间的差异。
5. 需要同步到 GitHub 时再选择“推送”；本地提交不会自动上传。

修改较多时，可先从 `main` 新建功能分支，例如 `feature/csv-detection`。测试确认后再合并回 `main`。

## 已设置的基线

`local-baseline-20261017` 标记了建立本地版本管理时的源码。以后可将新代码与这个标记比较。基线保留了当前产品管理功能、STDF 信息查看及稳定性整理。

只有提交过的内容才进入历史。重要修改完成后及时提交；提交不能代替异地备份，电脑磁盘损坏时本地版本库也可能丢失。需要备份源码时，可将确认过的提交推送至现有 GitHub 仓库。

## 哪些文件会保存

- 保存：C#、XAML、项目文件、图标、文档和通用示例 `config.ini`。
- 忽略：`bin`、`obj`、`.vs`、发布产物、清理归档、诊断输出、本地测试数据、个人设置和数据库。
- 产品管理数据库和外部 CSV/STDF 不由 Git 备份，继续按原方式保存；不要将生产数据或凭据强制加入版本库。

忽略规则见项目根目录的 `.gitignore`。不要删除 `.git` 隐藏目录，它保存本地历史和配置。

## 可选命令

在项目目录打开终端后可执行：

```powershell
# 查看本次改了什么
git status
git diff

# 查看最近版本
git log --oneline --decorate -10

# 保存本次源码修改（先确认 git status 和 git diff）
git add -A
git commit -m "说明这次修改"

# 查看与初始基线的差异
git diff local-baseline-20261017

# 明确需要同步到 GitHub 时再执行
git push origin main
```

若需要恢复旧版本，先提交或暂存当前修改，再在历史中比较或还原目标提交。不要使用强制推送或清理未跟踪文件来解决普通同步问题。
