# 整体流畅度优化方案

建议先把管理器的源文件状态检查移出筛选流程，再缩短分析器导入完成后到列表可操作的等待。前者在共享盘离线时尤其重要，后者决定用户看到进度走到末尾后还要等多久。这两处都有明确的同步调用，可以独立测量和交付。直方图和批量合并的改法会增加索引或改变数据所有权，排在基线测量之后。

**评审基线**　2026-11-23，项目版本 2.0.20。本文基于 2026-11-19 更新的交接说明，并对照了 `main` 的提交 `f0a71f9`。方案以 Windows x64、.NET 8、WPF 的实际操作为验收环境。[交接.md](../交接.md) · [评审时的源码](https://github.com/ttt3t/semiconductor-data-analyzer/tree/f0a71f98ea25b2a6e067888c58164183a47d9de8)

## 一、先看用户等在哪里

| 用户动作 | 当前代码做了什么 | 第一轮要量什么 |
| --- | --- | --- |
| 启动管理器、输入批次或切换统计周期 | 构造窗口时同步读取产品目录。筛选已有 150 ms 防抖，触发后仍在界面线程检查快照和源文件状态，最后刷新良率、Bin 分类、不良分类三张图 | 首窗可操作时间、每次筛选访问文件系统的次数、当前页与隐藏页各花多少时间 |
| 打开或追加文件，等待列表可用 | 解析、身份匹配、复测选择和摘要已在后台完成。最后的 `CommitAnalysis` 会建立租约、初始化 Run、绑定及筛选列表 | 分开记录读取、统计、界面提交、第一行可选、首对图表就绪，特别看最后两步的间隔 |
| 查找测项、连续切换 Run | 表格已有虚拟化和滚动合并。列筛选在界面线程设置视图谓词。Run 切换逐行更新摘要的 Value，右键筛选弹窗同步去重、排序 | 展开 Site/Wafer 后的摘要行数、输入到回显、最后一次输入到结果、弹窗首次可操作时间 |
| 拖动直方图、打开晶圆 Map | 直方图已缓存当前测项统计和散点，也会合并连续拖动。每次真正重分箱仍扫描当前样本。累计 Map 已后台生成，普通 P/F、SBIN、HBIN Map 在打开窗口前同步构造页面 | 相邻两次有效更新之间的时间、松手到最终精确图、点击 Map 到首片可读 |
| 导出带关注项的 XLSX，同时继续看数据 | 分析报告已有独立 STA 绘图线程、数据租约和临时文件。合并 Site 和 Wafer 时，关注项可能连续计算两份覆盖相同样本的摘要 | 摘要、制图、工作簿保存分别耗时多少，导出期间主窗口输入是否延迟 |

## 二、建立可重复的 Windows 基线

使用同一台机器、相同电源模式、Release x64、相同 DPI、窗口大小、INI 和操作顺序做前后对照。记录 CPU 型号、内存、磁盘类型、数据行数、测项数、有效测量数、Site/Wafer 数及文件数。分别记录新进程启动、首次读取、同进程再次读取三个场景，并注明操作系统文件缓存状态。

| 样本 | 建议起始规模 | 用它复现的动作 |
| --- | --- | --- |
| A · 日常交互 | 1,000 条记录 × 1,000 测项的 CSV，4 个 Site、数片晶圆 | 单文件导入，展开/合并 Site 和 Wafer，输入中文和数字筛选条件，连续切 20 次 Run，核对 Value |
| B · 单测项很多记录 | 至少 1 个测项含 10 万个有效数值，另备整数重复值、刚好等于阈值及缺测的样本 | 从默认视野开始连续拖动 5 秒、滚轮缩放、双击恢复。依次测试三种分箱模式、散点标记及多片 Map |
| C · 多来源 | 同一批记录分别装成 1、10、50 个等量文件，固定总记录数、有效测量数、文件顺序和匹配选项。另设含多工作表 Excel、ZIP 成员、gzip STDF 的兼容性小样本 | 首次批量打开、向已有数据追加、末个文件损坏、中途取消。单独记录定义合并和最后建列耗时 |
| D · 产品管理与并行使用 | 约 300 条登记，含多个批次、重复物理路径、手工指定良率。分别使用本地盘、慢共享盘和离线来源 | 连续输入筛选词、切产品和周期、查看未访问的标签页。主窗口滚动时从独立分析器导出带关注项的报告 |

**怎么量。** 用 `Stopwatch` 记阶段起止和数据规模，诊断版在后台按固定节拍投递最多一个待处理的 Dispatcher 回调，记录从入队到执行的延迟。输入事件另记到首个可见反馈、最终内容完成后首个渲染帧的时间，避免把防抖等待误计成界面卡死。用 PerfView 或 Windows Performance Recorder 对最长停顿抓一次 CPU、GC 与文件 I/O 调用栈。交互每场景至少取 30 次有效操作，报告 P50、P95 和最大值。长导入和导出各重复 5 次，报告中位数和范围。记录峰值私有字节、GC 暂停、临时文件占用。反复开关窗口的内存用自然回收模式对比。

**建议的首轮验收目标**

| 指标 | 目标与适用条件 |
| --- | --- |
| 操作反馈 | A、D 中输入字符或选择条件到首个可见反馈 P95 ≤ 100 ms。有活动操作时，单次超过 200 ms 的 Dispatcher 排队延迟逐条查栈 |
| 列表与管理器筛选 | A、D 本地场景中，最后一次按键至当前页最终结果 P95 ≤ 300 ms，含原有防抖。慢盘场景中，筛选本身触发的源文件状态探测次数为 0，当前页可先显示上次快照 |
| 导入收尾 | A、C 中，从开始提交到列表可操作的中位数比基线降低至少 30%。导入总耗时同时记录。若基线该段已 ≤ 100 ms，则维持该水平即可 |
| 图表交互 | B 中，持续拖动时有效视野更新间隔 P95 ≤ 100 ms，松手至精确分箱 P95 ≤ 150 ms。单独记录首次选中测项的耗时与新索引成本 |
| 吞吐和内存 | 同一输入下，非目标路径的导入/导出中位耗时与峰值私有字节分别控制在基线的 110% 以内。重复开关 12 轮，检查关闭后仍被引用的快照、窗口和临时文件 |

## 三、第一轮实施顺序

### 1. 管理器先显示已有结果，再异步核对文件

`RefreshDetails` 先调用 `ProductYieldService.IsCurrent`，再为文件表遍历登记项。两个位置均可能按文件 ID 线性查找快照记录并读取文件元数据。筛选结束还会调用三个趋势刷新方法。`ManagementTrendView.SetData` 会移除旧动态列再逐个添加。一次慢路径访问就可能让同一界面线程上的输入一起等待。[管理器刷新入口](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/ProductManagementWindow.xaml.cs#L86) · [快照有效性检查](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/ProductYieldService.cs#L49) · [趋势表建列](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Controls/ManagementTrendView.xaml.cs#L31)

1. 打开产品时先从已保存的摘要填充当前页，文件状态标出“核对中”或上次核对时间。首次打开、重新定位、保存配置、完成重算及显式核对时启动后台检查。同一轮按快照建立 `FileId` 索引，按物理路径去重读存在性、长度和修改时间，再分发到各登记项。手工指定良率沿用原有判断。
2. 筛选和周期切换只重算内存投影。先刷新可见页，其余页记录所需的产品版本、周期和筛选条件，首次显示时再计算。若趋势表的列标签与顺序相同，复用已有列，更新值和列格式。图例选择、图表和表格横向对齐、报告所取布局继续按现有规则处理。
3. 慢盘检查采用有上限的后台并发。切换产品或关闭窗口后丢弃旧任务结果。操作系统尚未返回的同步 I/O 也占用并发额度。快照、登记或配置已变化时，旧结果不得覆盖新状态。导出前沿用原有的有效性复核与必要重算，复核也放在后台。若启动采样指向目录 JSON 读取，再让窗口先显示、后台只读加载，完成后开放产品编辑。
4. **验收方法。** 共享盘离线时仍能输入筛选词、切换周期、打开独立分析器。切换产品后让旧检查返回，当前产品状态应保持正确。用同一报告选项核对原始 HBIN 良率，综合良率仍以必测步骤芯片并集为分母。另查隐藏图例后的分类占比、列宽和分页。

### 2. 把导入收尾的索引准备移出界面线程

`PrepareAnalysisAsync` 已在后台构建摘要。随后 `CommitAnalysis` 创建的 `DatasetLease` 会遍历记录以取得唯一原始存储。数据替换时 `InitializeRun` 还要逐条建立 SN、LOT/Wafer/XY 索引。有样本范围时另建记录 ID 集合。批量打开与追加完成后又逐来源保存最近文件。这几段都值得单独计时。[准备和提交](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/MainWindow.xaml.cs#L579) · [Run 索引](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/MainWindow.Run.cs#L47) · [数据租约](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/AnalysisOperation.cs#L33) · [批量入口](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/MainWindow.OpenFiles.cs#L26)

1. 先将耗时最大的纯数据工作并入后台准备结果。从最终的 `prepared.Source` 建 Run 索引，沿用已有的同源快照复用逻辑。启用样本范围时，同时从 `prepared.Scope` 生成所需 ID 集合。界面线程只校验操作仍有效、交换引用、恢复选中行并安排首对图表。租约若随准备结果转交，必须在原操作释放临时存储前取得，取消或异常时由准备结果释放，提交成功后由窗口接管。
2. 保留原记录顺序。重复 SN 继续取首次匹配，坐标定位取同 LOT 和 Wafer 中的末次记录，上下键仍能浏览各次原始记录。继续使用当前按 100 ms 拉取的导入进度。将真正耗时的阶段显示清楚。若最近文件写盘占用明显，将一批路径按原有次序应用到内存历史，保留去重及 20 条上限，成功后一次原子写入。多个窗口共用历史时按提交顺序串行保存。
3. **验收方法。** 分别测试单文件、批量、追加、应用筛选。让批量的最后一个来源失败，或在建索引中取消，原数据、原选择及已打开的子窗口仍可使用。交替导入大文件和小文件，确认替换后旧索引空间能随最后一个持有者释放。

### 3. 让测项搜索和 Run 切换只做本次需要的工作

`ApplySearchFilter` 在 UI 上设置 `ListCollectionView.Filter` 并找回选中行。`MatchesColumnFilters` 每行遍历各列状态。即使表格只绘制可见行，筛选仍可能遍历全部摘要。右键菜单构造时还会对该列全部显示文本去重和排序。Run 的数值读取已经直接走数值列，剩余成本是对每个摘要赋值和通知。[视图筛选](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/MainWindow.xaml.cs#L745) · [右键值列表](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Controls/ColumnValueFilterPopup.xaml.cs#L34) · [Run 值更新](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/MainWindow.Run.cs#L165)

1. 每次条件变化先整理已启用的规则和取值列。无条件时清空谓词，有条件时只求规则所需的文本或数值。在同一次视图刷新中恢复排序与选择。较大列表若仍超标，再对只读值快照后台生成有序命中行，UI 一次应用最终版本。Run、关注状态和数据源变化都要使相关结果失效。
2. 右键菜单先显示框架。若该列取值多，在后台用原有显示格式和比较器分组、排序，完成后绑定。优先缓存近期打开的静态列，按摘要版本和列设上限。Run 与关注列依赖当前状态。滚动继续用 `FastDataGrid` 现有的输入合并、行复用及停止滚动后恢复详情的逻辑。
3. 普通连续切 Run 时可将同一渲染帧内的多次全表刷新合并一次，按实际按键次数算出最终行。若按 Value 排序、搜索、勾选取值或复制整表，必须使用同一个最终 Run 的完整结果。验收覆盖中文输入法组合、右键接管同列搜索、按数值排序百分比、升序→降序→默认、重复测项名和清空筛选后恢复选择。

## 四、按实测决定的第二轮

### 直方图拖动

若样本 B 的耗时集中在 `CreateRangeBins` 遍历样本，优先缩短反复计数的时间。保留 `DetailCache` 和当前“完成一次、处理最新视野”的调度。只对反复拖动的大测项试做有限数值排序索引。沿用现有分区和箱边界，按每箱端点的开闭选择二分位置差得到计数，两端另算视野外样本。连续值比较用原数值域，整数分箱沿用显示因子和现有整数边界。首图走原路径，索引只覆盖一个测项的 Site/Wafer 样本集合，连续平移时复用。新增的排序数组按每个有效样本约 8 字节计入预算，建索引前检查可用额度，切换测项或取消时释放。

**验收与回退。** 与扫描版逐箱比较上下界、开闭、数量、区间颜色、左右溢出及百分比。覆盖单值箱、等于 LSL/USL、仅单边有效、隐藏超规、非有限值及对数显示。数量百分比与累计百分比均以视野内参与绘图的样本为分母，左右溢出单列。复制 PNG 取当前视野，报告按导出模式用默认范围。任一计数不一致、内存超限或没有可重复收益即回到扫描路径。[分箱](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/HistogramService.cs#L123) · [详情缓存](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/DetailCalculator.cs#L104)

### Map 首次打开

样本 B 的停顿集中在构页或首片布局时再实施。点击时固定数据、测项、Site、Wafer 与配置，取得本次所需租约。先显示独立窗口及加载状态，后台生成普通 Map 页的数据，控件和可变画刷留在 UI 线程。Bin 页当前会为每片晶圆重新遍历设备，可按 LOT/Wafer 一次分组并沿用原页序。回到 UI 设置页面并选择原目标晶圆。关闭该 Map 后取消其任务，待后台停止读取再释放租约。已打开窗口继续持有自己的快照，累计视图沿用现有后台构建和可见行绘制。

**验收与回退。** 慢任务期间仍可滚动主表。关闭原分析器或换数据后，已打开的 Map 仍对应点击时的数据。检查跨 LOT 同名片/同 XY、无坐标提示、累计图每坐标的分母及复制表格。[普通 Map 入口](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/MainWindow.xaml.cs#L1349) · [按片构页](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/MapDataService.cs#L41) · [累计视图](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/WaferMapWindow.Cumulative.cs#L44)

### 多文件合并

用样本 C 检验在总测量数固定时，多拆几个来源是否会显著拉长定义合并。`ReadSources` 已在批尾统一建列。每轮 `MergeDefinitions` 仍会克隆累计的旧记录。先统计克隆行数与分配量。若成为主耗时，引入仅由本次批次持有的记录列表，向已有数据追加时先隔离已发布的可变记录，后续按所选来源顺序追加和映射，复用底层只读测量存储。批尾照常统一建列、规范化序号、一次提交。

**验收与回退。** 同输入逐条比对顺序、复测、测项分项、单位换算和选新/旧阈值、UUID、警告和整合 CSV 重开结果。失败或取消时只丢弃本批次资源，旧窗口继续可读。若收益小于前后测波动，保留现有合并路径。[来源循环](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/DatasetService.cs#L260) · [旧记录克隆](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/DatasetService.cs#L481)

### 分析报告导出

样本 D 的关注项统计耗时突出或导出期间输入延迟超标时再实施。保留现有 STA、按测项处理和临时文件替换。当报告主表同时合并 Site 和 Wafer 时，复用本测项刚生成的同口径摘要给关注页。分组、选片、离群规则或样本集合不同时按各自口径计算。复用已有导出阶段信息发布低频进度，分别量化绘图与 ClosedXML 保存阶段。

**验收与回退。** 对比工作表行数、统计单元格、图中分箱和散点顺序。导出时切换主表，随后关闭原分析器，导出仍能完成。取消停在库内保存时显示正在取消，回到可检查点再退出，原目标文件完整。以 UI 延迟和报告总耗时共同判定收益。[逐项导出与最终写入](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/XlsxReportService.cs#L143)

### 统计占满 CPU 或内存

采样指向并行摘要或 GC 暂停时再实施。`SummaryService` 已按测项并行，精确中位数利用池化缓冲排序。固定同一宽表，分别用现有并行度、较小并行度测总耗时、峰值临时缓冲和输入延迟。只在能改善交互且总耗时仍在预算内时采用新的并发上限。

**验收与回退。** 精确中位数、离群规则、Site 良率和空组输出逐项对齐。保留按生命周期触发的空闲回收策略。只有暂停调用栈指向此处才单独评估 GC 参数。[摘要分组](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/SummaryService.cs#L13) · [中位数计算](https://github.com/ttt3t/semiconductor-data-analyzer/blob/f0a71f98ea25b2a6e067888c58164183a47d9de8/Services/StatisticsService.cs#L139)
