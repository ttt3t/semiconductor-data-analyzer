# V2.1.0 磁盘存储与性能记录

## 实现范围

完整测量数值按测试项写入连续二进制段；稠密列省略行号，稀疏列同时保存原行号。CSV 使用 double，STDF 仅在无损时使用 float。导入使用不超过 16 MiB 的转置缓冲，不先建立整份数值矩阵。原文仍按行保存在独立快照，缺测、无效文字和 UUID 原文保持原有语义。

SQLite 保存身份、SN/XY/芯片/设备索引、统计结果和排序工作表。身份对象按 64 行分页；复测按芯片流式处理，每个测试项独立保留首测/末测/后续复测。筛选视图共享源列，只保存分页行映射。统计缓存键包含数据会话、范围、测项、Site/Wafer、限值、异常处理、显示系数与格式。精确中位数在超过 1,048,576 个值时采用有限路数的外部排序，不抽样。

散点序列和大标记集合分页；后台读取当前可见范围，使用原点印章、原覆盖顺序和全部真实点绘制位图。旧图保留到新图就绪，过时请求取消。大统计表和管理表格不再建立完整 WPF 对象副本，筛选/排序位置可以落盘。BIN、Wafer 统计和模拟所需的大状态/行号矩阵也走磁盘索引或分页向量；Map 的芯片元数据分页保存，可见 Map 控件仍有绘图和命中测试开销。

产品/芯片管理的同温复测和跨温匹配改用磁盘主键；综合良率每次只读取一颗芯片的各温度观察值。每个输入文件先写临时事务，失败或读取中变化的文件不贡献部分芯片。CP 的批次+晶圆+XY、FT 的批次+UUID、指定良率、月归属、缺温/缺身份及源文件关联保持原口径。产品目录仍是兼容的 `catalog.json`，改为流式读写、磁盘事务副本和原子替换，保留 `.bak`。登记定义和最终小型汇总仍驻留内存。

常规磁盘数据的 Fail XLSX、分析报告 XLSX、管理报告 XLSX 在同一个 EXE 的内部工作进程中运行。主进程传小型任务清单和只读缓存位置，不发送全量测量矩阵；一次只允许一个导出进程，子进程页缓存为主程序档位对应缓存的四分之一（24/48 MiB）。取消时终止子进程，成功后才替换最终目标文件。子进程退出时释放报表程序集、JIT 和工作对象；小型手工构造/编辑的非磁盘数据保留兼容的进程内导出路径。

## 内存与生命周期

“界面与习惯”提供 256/512 MiB 档位，默认 256 MiB。共享 LRU 页缓存分别为 96/192 MiB，所有小型行号向量另有合计 8 MiB 的溢写阈值，完成写入后释放写缓冲。其余为有界转置、排序、统计与绘图工作缓冲预留；转置、统计和光栅任务共用两个进程级工作槽。此档位是数据缓存策略，不是操作系统强制的进程内存上限，WPF 可见对象、运行库、SQLite、报表进程与系统文件缓存另有开销。多窗口共用一个进程级 LRU。

缓存位于 `%LOCALAPPDATA%\SemiconductorCsvAnalyzer\Cache\v1`。工作文件以进程 ID 和随机值命名，操作取消/失败会释放未发布资源；数据集只在构建成功且源文件检查通过后交给窗口。使用者以租约保留快照，最后一个使用者释放后关闭相应文件。异常退出残留在下一次使用缓存时按存活进程检查清理。工作进程清单带格式版本、长度和行数约束。

本版使用**会话临时缓存**，没有跨次打开复用，因此不会把只凭文件名/时间判定的旧缓存当作新数据。源文件读取期间继续检查长度和修改时间。无需改变数据文件位置；缓存构建、清理均不修改源文件。闲置处理只淘汰可重建页缓存，不强制 GC 或清空进程工作集。

## 可复现基准

环境：Linux 云端、.NET SDK 8.0.426、工作站 GC。合成 CSV 为 400,000 条记录、200 个稠密 double 测项、4 个 Site、无复测，每个值 1.25；源文件约 391 MiB。优化前取 V2.0.6 提交 `bbae18d736927414876765aa4fc7b59d6e18aeaa` 的核心实现，与优化后使用同一份 CSV。以下为单次测量，包含页缓存/GC 的波动，不能代替真实 Windows、机械硬盘或稀疏 STDF 的结果。

| 项目 | V2.0.6 | V2.1.0 |
|---|---:|---:|
| 加载后托管堆 | 820.5 MiB | 0.86 MiB |
| 加载后工作集 | 885.7 MiB | 88.9 MiB |
| 全过程进程峰值工作集 | 887.5 MiB | 273.1 MiB |
| 完成首次统计后托管堆（含热页） | 807.0 MiB | 109.4 MiB |
| 导入 | 14.88 s | 43.82 s |
| 首次统计 | 1.50 s | 5.47 s |

优化后第二次相同条件统计为 0.008 s，完成后的结构化缓存约 888.2 MiB（不含行式原文与构建期间的转置临时文件）。

这说明数值规模不再直接决定加载后的常驻托管堆；峰值工作集在本例下降约 69.2%。代价是转置、身份索引和冷读增加 I/O；完整缓存还包括行式原文与列式数值两份组织，构建期间另需转置临时空间。建议 SSD 并预留源文件数倍空间。不能用这里的常驻堆降幅推断所有数据的进程峰值降幅。

运行 `bash Tests/run-storage-benchmark.sh /path/to/data 400000 200` 可生成/复用同一 CSV 并输出 JSON，包括导入/冷统计/热统计时间、托管堆、峰值工作集和完成后结构化缓存大小。基准中的显式 GC 仅用于测量保留对象，不属于产品路径。对照旧版本时，把此脚本和 `StorageBenchmark.cs.txt` 复制到旧版本 checkout 的 Tests 后运行。
